# 開発計画

## このリポジトリについて

このリポジトリは、製造業の生産データを意思決定に利用できる形に整備する過程を通じて、製造業DXと分析基盤開発の実務能力を示すためのポートフォリオである。

合成製造データを用いて、コイルの生産指示から工程通過、完成、品質判定までを追跡できる分析基盤を構築する。シフト別生産量、歩留まり、工程時間、品質逸脱を再現可能なKPIとして提供し、データモデリング、品質保証、運用設計、可視化までの一貫した実装を行う。

ソースデータの生成には、別リポジトリで開発した `manufacturing-data-generator` を使用する。本リポジトリではジェネレータ自体の改修は行わず、生成されたソースデータ以降の変換・モデリング・運用・可視化を対象とする。

## 対象とする業務上の問い

構築する分析基盤は、少なくとも次の問いに答えられるものとする。

- 指定期間に、シフトや班ごとにどれだけ生産したか
- 生産指示から完成までにどの程度の時間を要し、どの工程で遅延しているか
- 不良、リジェクト、寸法逸脱はどの程度発生しているか
- シフト、班、材質などの切り口によって、生産性や品質に差があるか
- 欠損、工程未到達、長時間停止などの異常により、KPIの信頼性が損なわれていないか

## KPI

最初のリリースでは、次のKPIを対象とする。実装前に各KPIの定義、粒度、分母・分子、対象外条件を文書化する。

- 生産量（コイル数、重量）
- 完成率と歩留まり
- リジェクト率
- 寸法・重量の規格適合率
- 生産リードタイムと主要工程時間
- シフト別・班別の生産性と品質

合成データは実設備の統計分布を表さないため、KPIの数値自体を業務上の結論として扱わない。このポートフォリオでは、定義の明確さ、計算の正確性、変更への再現性を評価対象とする。

## 開発目標

技術要素は目的ではなく、上記の業務上の問いに安全かつ再現可能な形で答えるために用いる。

- Docker ComposeによるPostgreSQL、dbt、Supersetの実行環境の構築
- stagingレイヤーでの型変換、名称統一、欠損・センチネル値の取り扱い
- intermediateレイヤーでの生産指示、工程通過、完成実績、シフトの紐付け
- martsレイヤーでの分析粒度とディメンションの整理
- コイルの進捗を表すAccumulating Snapshot Factの実装
- 必要性を業務上説明できる場合に限ったFactless Factの実装
- dbt testsによる一意性、必須性、参照整合性、値域、業務ルールの検証
- Prefectによるデータ生成・変換・検証の定期実行と失敗時の可視化
- SupersetによるKPIとデータ品質のダッシュボード化
- データ量、実行時間、クエリプランの計測とボトルネックの説明

## 完成条件

最初の完成版は、次の条件をすべて満たすものとする。

- 初期化された環境から、文書化された少数のコマンドで環境構築、データ生成、変換、可視化を再現できる
- 同じ設定とseedから同じソースデータを再生成できる
- `dbt build` が成功し、想定する正常系と異常系をdbt testsで検証できる
- すべての公開KPIに定義、粒度、計算根拠、除外条件がある
- ダッシュボードが「対象とする業務上の問い」に答えられる
- 欠損、リジェクト、工程未到達、長時間停止を含むデータを安全に処理できる
- 基準データ量に対する各処理の実行時間を計測し、主なボトルネックと改善候補を説明できる
- READMEにアーキテクチャ、起動手順、データフロー、主要な設計判断、制約事項が記載されている

## 開発フェーズ

### Phase 1: スコープと契約の固定

- ソーステーブルと主要列の役割を整理する
- KPI定義と業務上の問いを文書化する
- データ粒度、キー、時刻、単位、センチネル値の取り扱いを決定する

### Phase 2: 再現可能な開発環境

- PostgreSQL、dbt、Supersetの起動構成を整備する
- 合成データ生成と初期化の手順を自動化する
- バージョン固定、設定例、ヘルスチェックを整備する

### Phase 3: dbtモデルとデータ品質

- sourcesとstagingモデルを構築する
- intermediateで業務プロセスを紐付ける
- martsと必要なFact・Dimensionを構築する
- データ契約と業務ルールをdbt testsで検証する

### Phase 4: KPIとダッシュボード

- KPI用マートとデータ品質モニタリングを構築する
- 業務上の問いごとにダッシュボードを整備する
- フィルター、単位、ツールチップ、欠損時の表示を検証する

### Phase 5: 運用と性能

- Prefectで定期実行と失敗時の状態を可視化する
- 処理の冪等性と再実行性を検証する
- データ量を変えた実行時間とクエリプランを計測する
- 制約、トレードオフ、未実装範囲を文書化する

## スコープ外

初回の完成版では、次の項目を対象外とする。

- 実設備や実在企業の性能・品質に関する結論
- ジェネレータが提供しないソーステーブルの追加
- 機械学習による予測・異常検知
- クラウド環境への本番デプロイ
- 高可用性構成や大規模分散処理

## 工数と見直し

本リポジトリはプライベート時間で開発する。各フェーズの着手前に実装項目を分解し、見積もりと完成条件を記録する。

フェーズ完了時に次のフェーズのスコープを見直す。時間が制約となる場合は、完成条件に寄与しない技術要素を削り、データフローとKPIの信頼性を優先する。
